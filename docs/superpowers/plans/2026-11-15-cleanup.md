# Cleanup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the small items left in the follow-ups file that need no hardware to fix: Core hardening and tests, a host test for the driver's `CoreHost`, three app texts and one leak, and the scripts' edge cases. Nothing a user of the port would notice changes.

**Architecture:** Core gains a small `util` unit (the helpers the driver duplicated) and tests; `CoreHost` talks to USB through a new DriverKit-free interface that `UsbIo` implements, so a host test binary can drive it with a fake; the app moves two decisions into its model where `make app-test` checks them; the install script's two decisions move into a sourced file with a test. The controller then installs one build and checks it on the modem.

**Tech Stack:** C++17 (Core: `-fno-exceptions -fno-rtti`, must pass `make check-driverkit`), DriverKit, Swift 5, POSIX `sh`, Python 3.

**Spec:** `docs/superpowers/specs/2026-11-13-rmnet-driver-design.md`; the items come from `docs/superpowers/plans/2026-11-13-core-and-harness-followups.md` (named per task).
