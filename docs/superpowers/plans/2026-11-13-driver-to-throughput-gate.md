# Driver to the Throughput Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the DriverKit extension that presents the RM520N-GL as an Ethernet port carrying real traffic, and measure its throughput against the gate in the design.

**Architecture:** One DriverKit class, an `IOUserNetworkEthernet` subclass, owns the network interface and forwards every event to two plain C++ classes: one for USB I/O and one that drives Core. Core does all protocol work, unchanged. A minimal command-line host app installs the driver. Recovery (unplug, sleep and wake, soak) and the real app are a later plan.

**Tech Stack:** DriverKit SDK 27.0 (NetworkingDriverKit, USBDriverKit), C++17, Swift for the host, an Xcode project generated by a Ruby script (`xcodeproj` gem), Core from this repository.

**Spec:** `docs/superpowers/specs/2026-11-13-rmnet-driver-design.md`

**Also read:** `docs/driverkit-notes.md` (every DriverKit API this plan uses, each proven by compiling, and the list of what only a running driver can settle) and `docs/superpowers/plans/2026-11-13-core-and-harness-followups.md`.

## Global Constraints

- Core's rules are unchanged: `core/` is plain C++17 with no heap, STL, exceptions or RTTI, only `<stdint.h>`, `<stddef.h>`, `<string.h>`; `make test` needs no hardware; `make check-driverkit` must pass.
- Driver code (`driver/`) may allocate with `new` and `IOLib`, but uses no STL, no exceptions, no RTTI.
- The driver attaches only to USB interface 4 of device `2c7c:0801`, and checks class, subclass and protocol `0xff` in `Start` before opening it. It never touches interfaces 0 to 3.
- No persistent modem changes: only the QMI messages Core already sends.
- No private macOS interfaces, no root helper, no `utun`, no SIP change, no `systemextensionsctl developer on`.
- No code copied from qmi-darwin or any unlicensed driver source. `scratchpad/dext-spike` is this project's own throwaway code and may be reused.
- Signing: team `ABCDE12345`, Xcode automatic signing, `-allowProvisioningUpdates`. Bundle identifiers: app `io.rmnetdriver.RMNet`, driver `io.rmnetdriver.RMNet.driver`. Entitlements exactly as in `docs/driverkit-notes.md` section 4.2.
- The host app is installed at `/Applications/RMNet.app`. Every build that is installed gets a new `CFBundleVersion` (a timestamp), so activation replaces the running driver.
- Every DriverKit override and completion logs one `os_log` line when it is first called, prefixed `RMNet:`, so the log shows which callbacks macOS really uses.
- Everything in the driver runs on the Default dispatch queue. Core is never called from inside one of its own delegate callbacks.
- Never use `sudo`. Steps that need the owner (an admin password, an approval in System Settings) are marked **Owner step**; stop there and report.
- Tests that use the network bind to the modem's interface with `/usr/bin/curl --noproxy '*' --interface <if>`, and confirm with `netstat -I <if> -b -n` that the bytes went through it. The shell sets proxy variables and its default `curl` does not bind.
- The modem's port must not become the Mac's primary network service. After the port first gets an address, check `scutil --nwi`; if it is listed first, stop and report.
- Each throughput run uses about 250 MB of cellular data. Do not run more than the steps ask for.
- Commit at the end of every task on the working branch, with the message given.

## Review Focus

1. Frames from macOS before the link is up, or after it drops, are completed and dropped; a transmit packet is never leaked. Check: Task 6 Step 4.
2. The driver starts before the modem's QMI answers; it retries the sync and comes up. Check: Task 5 Step 5.
3. The receive pool runs out under load: packets are dropped and counted, and bulk reads keep being re-posted. Check: Task 7 Step 3.
4. A stuck bulk OUT transfer does not stop the timer, the control channel or the downlink. Check: Task 6 code review, and Task 7 Step 3 counters.
5. The modem is unplugged while traffic flows: the driver process stops without a crash report, and replugging brings a fresh instance up. Check: Task 6 Step 6.

### Task 1: Core retries a family that failed while the other came up

**Files:**
- Modify: `core/include/rmnet/session.h`, `core/src/session.cpp`, `tests/test_session.cpp`

**Interfaces:**
- Consumes: the existing `Session`.
- Produces: no signature change. New behaviour and one new constant set in `session.h`:

```cpp
enum : uint32_t { kFamilyRetryFirstMs = 5000, kFamilyRetryMaxMs = 60000 };   // 5 s, 10 s, 20 s, 40 s, then 60 s
```

Behaviour:

- When the session is Up with one family carrying the link and the other not, it retries the missing family: first `kFamilyRetryFirstMs` after `link_up`, then doubling, capped at `kFamilyRetryMaxMs`.
- A retry reuses the family's existing WDS client: it sends Start Network, and on success Get Current Settings. If the family has no client (the Get Client ID failed earlier), the retry starts from Get Client ID, Bind Mux and Set IP Family.
- The session stays Up throughout. A retry that fails, or times out, schedules the next retry and changes nothing else: no `link_down`, no Backoff.
- When a retry succeeds, `link_up` is called again with the merged settings. `link_down` is not called first. `SessionDelegate`'s comment in the header says so: a second `link_up` while up means the settings gained a family.
- A disconnect indication from a family that carries the link still takes the link down and goes to Backoff, including while a retry is outstanding.
- Once both families carry the link, no retry is scheduled.

- [ ] **Step 1: Write the failing tests** in `tests/test_session.cpp`, using the file's existing helpers and three new local ones: `bring_up_v4_only(session, modem, time)` replays the capture so IPv4 comes up and the IPv6 Start Network fails, with the last response fed at `time`; `start6_response_with_txid(txid)` and `settings6_response_with_txid(txid)` are `kWdsStart6Resp` and `kWdsSettings6Resp` with their transaction IDs replaced

```cpp
TEST(missing_family_is_retried_while_up) {
  FakeModem m; rmnet::Session s({}, m); bring_up_v4_only(s, m, 100);          // helper: IPv6 Start Network fails at time 100
  CHECK(s.state() == rmnet::SessionState::Up); CHECK_EQ(m.ups, 1);
  size_t sent = m.sent.size();
  s.tick(5099); CHECK_EQ(m.sent.size(), sent);
  s.tick(5100); CHECK_EQ(m.sent.size(), sent + 1);
  CHECK_EQ(m.last()[5], 16); CHECK_EQ(m.last()[9], 0x20);                     // Start Network on the IPv6 client
  feed_frame(s, start6_response_with_txid(m.last_txid()), 5200);
  CHECK_EQ(m.last()[9], 0x2d);                                                // Get Current Settings
  feed_frame(s, settings6_response_with_txid(m.last_txid()), 5300);
  CHECK(s.state() == rmnet::SessionState::Up); CHECK_EQ(m.ups, 2); CHECK_EQ(m.downs, 0);
  CHECK(m.cfg.settings.has_v4); CHECK(m.cfg.settings.has_v6);
  sent = m.sent.size(); s.tick(200000); CHECK_EQ(m.sent.size(), sent);        // nothing left to retry
}
TEST(failed_retry_keeps_link_up_and_backs_off) {
  FakeModem m; rmnet::Session s({}, m); bring_up_v4_only(s, m, 100);
  const uint64_t at[] = {5100, 15200, 35300, 75400, 135500, 195600};          // waits of 5, 10, 20, 40, 60, 60 s after each failure
  for (uint64_t t : at) {
    size_t sent = m.sent.size();
    s.tick(t - 1); CHECK_EQ(m.sent.size(), sent);
    s.tick(t);     CHECK_EQ(m.sent.size(), sent + 1);
    feed_frame(s, failed_start_frame(16, m.last_txid()), t + 100);
    CHECK(s.state() == rmnet::SessionState::Up); CHECK_EQ(m.downs, 0); CHECK_EQ(m.ups, 1);
  }
}
TEST(retry_timeout_keeps_link_up) {
  FakeModem m; rmnet::Session s({}, m); bring_up_v4_only(s, m, 100);
  s.tick(5100); size_t sent = m.sent.size();
  s.tick(65099); CHECK(s.state() == rmnet::SessionState::Up);
  s.tick(65100); CHECK(s.state() == rmnet::SessionState::Up); CHECK_EQ(m.downs, 0);   // Start Network timed out
  CHECK_EQ(m.sent.size(), sent);
  s.tick(75100); CHECK_EQ(m.sent.size(), sent + 1);                           // next retry 10 s after the timeout
}
TEST(live_family_drop_during_retry_goes_to_backoff) {
  FakeModem m; rmnet::Session s({}, m); bring_up_v4_only(s, m, 100);
  s.tick(5100);
  feed(s, kWdsDisconnected4Ind, 5200);
  CHECK_EQ(m.downs, 1); CHECK(s.state() == rmnet::SessionState::Backoff);
}
```

### Task 5: USB and the QMI control channel

**Files:**
- Create: `driver/usb_io.h`, `driver/usb_io.cpp`, `driver/core_host.h`, `driver/core_host.cpp`
- Modify: `driver/RMNetDriver.iig`, `driver/RMNetDriver.cpp`, `gen.rb`, `docs/driverkit-notes.md`

**Interfaces:**
- `UsbIo` (plain C++, owned by the driver's ivars): opens the interface and copies its three pipes; raises DTR; keeps one interrupt read posted; reads encapsulated responses after a notification until none is left (64 at most) and splits them with `rmnet::qmi_frame_length`; sends control messages in order from a ring of 8 buffers of 128 bytes; reads the USB serial number string; aborts everything at stop. It reports through callbacks to its owner: `on_control(const uint8_t*, size_t)`, `on_fatal(const char*)`.
- `CoreHost` (plain C++): implements `rmnet::SessionDelegate`; owns `rmnet::Session` and `rmnet::EthernetEmulator`; `start(now_ms)`, `stop()`, `tick(now_ms)`, `on_control(...)`. `send_qmi` hands the frame to `UsbIo`. `link_up` and `link_down` only record the change; the driver applies it after the Core call returns.
- `RMNetDriver`: `Start` now opens USB, derives the MACs from the real serial number, starts a 100 ms timer that calls `CoreHost::tick`, and starts the session. On link up it sets the emulator's link, reports link active with the MTU from the settings, and publishes `RMNetState`, `RMNetIPv4`, `RMNetIPv6`. On link down it reports link inactive. `Stop` follows the order in notes section 3.9, and releases USB objects only after their aborted completions have arrived.

### Task 6: The data path

**Files:**
- Modify: `driver/usb_io.h`, `driver/usb_io.cpp`, `driver/core_host.h`, `driver/core_host.cpp`, `driver/RMNetDriver.iig`, `driver/RMNetDriver.cpp`, `docs/driverkit-notes.md`

**Interfaces:**
- `UsbIo` gains the bulk side: 32 reads posted on bulk IN, each sized to the granted downlink size, re-posted after every completion, with stall recovery limited to 5 consecutive failures per read before `on_fatal`; and 8 uplink buffers sized to the granted uplink size, sent asynchronously. It reports `on_bulk_in(const uint8_t*, size_t)` and `on_bulk_out_done(int slot, bool ok)`.
- `CoreHost` gains:
  - Downlink: for each transfer, walk frames with `qmap_next`. A command frame gets the reply from `qmap_build_command_reply`, built in a separate buffer, and flow disable or enable pauses or resumes the uplink. A data frame goes through `EthernetEmulator::wrap_rx` into a receive packet. With no receive packet available, the frame is dropped and counted.
  - Uplink: each transmit frame goes through `EthernetEmulator::handle_tx`. `Reply` is delivered to macOS as a received frame. `Forward` goes into `QmapAggregator` on mux `0x81`; the buffer is sent when the transmit queue is empty or the aggregator is full. With all 8 uplink buffers in flight, transmit frames are dropped and counted. Every transmit packet is completed whatever happens to it.
  - An unsolicited router advertisement from `make_router_advert` on link up and every 600 seconds while up.
  - A second `link_up` while up updates the emulator's link and, if it gained IPv6, sends a router advertisement at once. It does not bounce the link.
  - Counters published as registry properties once a second: packets and bytes each way, drops each way with their cause, command frames, USB errors.

### Task 7: The throughput gate

**Files:**
- Create: `scripts/measure.sh`
- Modify: `driver/` as tuning requires, `docs/driverkit-notes.md`, `docs/superpowers/plans/2026-11-13-core-and-harness-followups.md`

**Interfaces:**
- `scripts/measure.sh <interface>`: resolves nothing through the system resolver; runs 4 parallel downloads for 8 seconds from `https://mensura.cdn-apple.com/api/v1/gm/large` and 4 parallel uploads for 6 seconds to `.../gm/slurp`, with `/usr/bin/curl --noproxy '*' --interface <interface> --resolve mensura.cdn-apple.com:443:111.132.43.41`; prints the total download and upload in Mbit/s; and prints the interface's byte counters before and after, failing if fewer bytes crossed the interface than `curl` reports.

The gate, from the design: if the driver cannot pass 150 Mbit/s down when the userspace tool can on the same day, stop and return to the owner. On 2026-11-13 the userspace tool measured 226 Mbit/s down and 36 up, and macOS's ECM driver 38 to 62 down.
